# タイムゾーン規則 (TIMEZONE_RULES.md)

1. **保存**: 時点は `timestamptz`(UTC)。APIは ISO 8601(`Z` 付き UTC)で入出力する。
2. **拠点ローカル**: 営業時間・例外日・シフトテンプレート・固定開始時刻・リソース利用可能時間は `time`/`date` で保存し、**拠点の IANA タイムゾーン**(例 `Asia/Tokyo`)で解釈する(Luxon)。
3. **日付境界**: 「今日」「予約日」「回数券の有効期限」「プランの期間」「KPIの日次」は拠点ローカル日付。組織横断の集計で拠点ごとにタイムゾーンが違う場合も、各予約はその拠点のローカル日付に属する。組織全体の期間指定(例: 9/1〜9/30)は各拠点のローカル日付で解釈する。
4. **DST**: 日本はDSTなしだが、実装は DST 対応(存在しない時刻はスキップ、重複時刻は早い方)。候補時刻は「ローカル時刻の刻み」を UTC に変換して生成するため、DST 移行日も壁時計どおり。
5. **日付をまたぐ営業/シフト**: 非対応(24:00 終了は可)。深夜営業は2日に分けて登録。
6. **表示**: 管理画面・公開ページとも拠点のタイムゾーンで表示し、端末のタイムゾーンと異なる場合は「(拠点時間)」を併記。
7. **ブラウザ入力**: 日時入力は拠点ローカルの「日付 + 時刻」で受け取り、サーバーで拠点タイムゾーンから UTC に変換する(端末TZに依存しない)。
8. **有効期限日**: その日を含む(`expires_on = 2026-10-31` なら 10/31 の拠点ローカル終日まで有効)。
9. **ジョブ**: 日次処理(期限切れ・期間締め)は5分毎のスケジューラが、各拠点のローカル日付を判定して実行(冪等キーで重複なし)。
10. テスト: `tests/unit/time.test.ts`(Asia/Tokyo, America/New_York の DST 境界を含む)。
