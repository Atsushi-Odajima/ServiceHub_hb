# KPI・計算ルール (CALCULATION_RULES.md)

会計売上/利益分析は扱わない。すべての指標は**期間を明示**し、**率は分母を明示**、**データがない場合は 0 ではなく「—(データなし)」**を返す(API では `null` + 理由)。

## 1. 期間
- 期間 [from, to] は拠点ローカル日付(両端含む)。予約は「開始時刻の拠点ローカル日付」で期間に属する。
- 組織横断(Owner)は拠点ごとに集計して合算。Manager は許可拠点のみ。

## 2. 予約系

| 指標 | 定義 | 分母 |
|---|---|---|
| 予約件数 | 期間内に開始する予約(全状態)の件数 | — |
| 完了数 | status = completed | — |
| 顧客キャンセル数/率 | canceled_customer / 予約件数 | 予約件数 |
| 事業者キャンセル数/率 | canceled_business / 予約件数 | 予約件数 |
| 無断欠席数/率 | no_show / (予約件数 − キャンセル数) | キャンセルを除いた予約件数 |
| 完了率 | completed / (予約件数 − キャンセル数) | 同上 |
| 利用人数 | 完了予約の party_size 合計 | — |

- 予約件数が0の期間の率は `null`(—)。
- 同一予約は1件として数える。拠点別の合計は全体と一致(予約は1拠点にのみ属する)。

## 3. 顧客
- 新規: 期間内に完了予約があり、その顧客の**最初の完了予約**が期間内にある顧客(人数)。
- リピーター: 期間内に完了予約があり、期間開始前に完了予約がある顧客(人数)。
- 顧客統合後は存続顧客として数える。匿名化顧客も件数に含める。

## 4. サービス別利用数
- 期間内に完了した予約の件数と人数(party_size)をサービス別に(予約時スナップショットのサービス名ではなく service_id で集計し、現在名を表示)。

## 5. スタッフ稼働率
```
稼働率 = 予約で占有された提供時間 ÷ 予約受付可能勤務時間
```
- **予約受付可能勤務時間**: 期間内の `work` シフト時間 − 重なる `break` / `vacation` / `training` / `other_work` / `block` の時間(重複は1回だけ差し引く)。拠点営業時間外の勤務時間も含める(勤務として登録されているため)。
- **占有された提供時間**: 期間内に開始した有効な占有(occupancy)のうち、1件以上の予約が completed / in_service / arrived / confirmed(未来)/ no_show のもの の**サービス時間 R**(buffer は含めない)。キャンセルで解放された占有は含めない。無断欠席は「予約で占有された」時間として含める(枠を確保していたため)。
- 分子は受付可能勤務時間と重なる部分のみ(シフト外の強制予約は分子から除外し、別途「シフト外予約」件数を表示)。
- 定員制の相乗りは占有1件として数える(二重計上しない)。
- 複数拠点: 占有は1拠点に属し、勤務シフトも1拠点に属する(同一スタッフの勤務は重複不可)。拠点別はその拠点の分子/分母、全体は単純合計(二重計上なし)。
- 分母が0(勤務登録なし)の場合は `null`(—)と表示し「勤務時間データなし」。
- buffer を含めない理由: 準備/片付けは提供時間ではない。buffer込みの占有率は将来の追加指標候補。

## 6. 回数券・利用プラン
- 回数券利用数: 期間内に作成された `use` エントリ数 − 同期間に作成された `use_reversal` 数(純利用)。
- 期限切れ間近: 基準日(今日)から30日以内に期限を迎える active かつ残数>0 の回数券数と残回数合計。
- 期限切れで失効した回数: 期間内の `expire` の合計。
- 利用プラン消化状況: 基準日を含む期間の 付与数合計 / 利用数合計 / 残数合計(active 契約)。利用率 = 利用数 ÷ 付与数(付与0なら null)。

## 7. 待機・通知
- 待機中件数(waiting)、期間内の待機→予約化件数。
- 通知失敗件数(failed、期間内作成)。

## 8. 検証テスト
- 必須 #20: 2拠点のKPIで拠点別合計 = 全体、同一予約の二重計上なし。
- 稼働率: 勤務8h・休憩1h・予約3h(buffer込み3.5h) → 3/7 = 42.9%。勤務なし → null。
