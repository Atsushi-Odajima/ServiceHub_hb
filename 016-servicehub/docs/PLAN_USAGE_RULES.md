# 期間利用プランの利用枠ルール (PLAN_USAGE_RULES.md)

決済サブスクではなく「期間内 N 回」の利用権管理。自動決済・請求は実装しない。

## 1. プラン商品 (plan_products)
- 名称、説明、対象サービス(個別 or 全サービス)、期間の長さ(月数、既定1)、期間内利用可能回数(uses_per_period)、期間の区切り方(alignment)、繰越可否(**既定OFF**)、繰越上限。

## 2. 顧客契約 (customer_plans)
- 開始日、終了日(任意・その日を含む)、状態(active / ended / canceled)、商品スナップショット、内部メモ。
- 商品設定を後から変えても、既存契約はスナップショットの条件で動く。

## 3. 期間 (customer_plan_periods)
- alignment = `calendar`: 暦月の1日〜末日(期間月数ごと)。開始月は開始日〜月末(**初月も満額付与**。日割りはしない)。
- alignment = `anniversary`: 開始日から期間月数ごと。月末起点は月末に丸める(1/31 開始 → 2/28(29) → 3/31)。
- 終了日があれば最終期間は終了日で打ち切り(満額付与)。
- 期間は重複不可(排他制約)。期間は必要時に遅延生成(消化時・表示時・日次ジョブ)し、生成時に `grant`(+N)を記録(期間ごとに1回、部分UNIQUE)。

## 4. 利用
- 利用日は予約開始の拠点ローカル日付。その日を含む期間の残数から消化(`use` −1)。
- 候補条件: 契約 active、利用日が契約期間内、対象サービス(スナップショット)、サービスが利用プラン対象、該当期間の残数 > 0。
- 回数券と同じ冪等・1予約1消化・取消戻し(`use_reversal`)のルール。
- 回数券とプランの両方が候補にある場合、どちらを使うかはスタッフが選ぶ(既定の選択はプラン → 期限の近い回数券の順で提案)。

## 5. 期間終了
- 期間終了翌日以降、日次ジョブが期間を closed にする。
  - 繰越OFF: 残数を `expire` で0に。
  - 繰越ON: min(残数, 繰越上限) を `carryover_out`(旧期間)/`carryover_in`(新期間)で移し、超過分は `expire`。繰越分は次の1期間のみ有効(次の期間終了で再計算)。
- 冪等キー: `plan_close:{periodId}`、`plan_grant:{periodId}`。

## 6. 例(必須テスト #4 / E2E-3)
- 月4回プラン: 期間付与 +4 → 3回利用 → 残1 → 4回目 → 残0 → 5回目は候補に表示されない(消化APIも INSUFFICIENT_BALANCE で拒否)。

## 7. 通知
- 契約終了日の N 日前(組織設定、既定7日)に「プラン期限のお知らせ」(冪等キー `plan_expiring:{planId}:{ends_on}`)。
