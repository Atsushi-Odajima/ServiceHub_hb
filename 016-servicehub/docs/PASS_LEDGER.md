# 回数券台帳 (PASS_LEDGER.md)

初版は「外部で購入済み/付与済みの利用権の管理」。オンライン決済・返金は扱わない。

## 1. データ
- `pass_products`: 名称、利用可能サービス(個別指定 or 全サービス)、初期回数、有効期間(日数・null=無期限)、説明、有効/無効。
- `customer_passes`: 顧客、商品、**付与時の商品スナップショット**(名称・回数・対象サービス)、付与日時、開始日、有効期限(その日を含む最終日)、初期回数、残回数(キャッシュ)、状態(active/expired/voided)、内部メモ。
- `pass_ledger_entries`(追記専用): 種別、増減、処理後残数、関連予約、関連実施記録、取消対象エントリ、理由、操作者(種別・メンバー・表示名スナップショット)、冪等キー、日時。顧客は回数券経由で参照(顧客統合時に台帳行を書き換えないため)。

## 2. 種別と符号

| 種別 | 意味 | 符号 |
|---|---|---|
| grant | 付与(回数券ごとに1回だけ) | + |
| use | 利用(予約/実施に関連付け) | − |
| use_reversal | 利用の取消戻し(元エントリを参照、1エントリにつき1回だけ) | + |
| manual_add | 手動追加(理由必須) | + |
| manual_subtract | 手動減算(理由必須) | − |
| expire | 失効(期限到来時の残数を0にする) | − |
| correction | 訂正(理由必須、符号自由) | ± |

## 3. 不変条件(DBで強制)
1. `customer_passes.remaining` は INSERT 時 0。以後は台帳 INSERT トリガのみが更新する。アプリからの直接 UPDATE はトリガで拒否。
2. 台帳は UPDATE/DELETE 不可(組織削除/置換復元時の明示フラグのみ削除可)。
3. 残数は負にならない(トリガで検査 + CHECK)。
4. `remaining = Σ delta`(台帳から常に再現可能)。`balance_after` は各時点の残数。
5. 冪等キー UNIQUE(組織内)。同じ操作の再送は既存エントリを返す。
6. 取消戻しは元エントリにつき1回(部分UNIQUE索引)。

## 4. 消化フロー
1. 完了時に利用可能候補を表示: 顧客の回数券のうち `status=active` かつ `remaining>0` かつ 開始日 ≤ 実施日(拠点ローカル) ≤ 有効期限 かつ 対象サービスに含まれる(スナップショット基準) かつ サービスが回数券利用可。
2. スタッフが「1回消化」を確認して実行(組織設定 `consumptionPrompt`: `on_complete`=完了ダイアログで候補表示 / `manual`=完了では出さず実施記録から後で消化)。**完了だけで自動消化はしない。**
3. 実行時: 予約行を `FOR UPDATE` → `consumption_entry_id` が空であることを確認 → 回数券行を `FOR UPDATE`(トリガ内)→ `use` エントリ INSERT → 予約に消化エントリを記録。冪等キーはクライアント生成(二重タップ・再送で同じキー)。
4. 同じ予約で2回目の消化は拒否(1予約につき有効な消化は1件)。

## 5. 取消
- 実施記録を取消す場合、消化があれば「回数を戻す/戻さない」を確認。戻す場合 `use_reversal` を INSERT し、予約の消化記録をクリア。戻さない場合も判断を監査ログに残す。
- 消化のみの取消(実施はそのまま)も Owner/Manager が可能(理由必須)。

## 6. キャンセル・無断欠席
- 締切前の顧客キャンセル/事業者キャンセル: 消化しない。
- 締切後の顧客キャンセル・無断欠席: 設定 `lateCancelPolicy`
  - `none`: 消化しない
  - `confirm`(既定): 予約を「消化確認待ち」にし、運営者が「1回消化」または「消化しない」を選ぶ(理由記録)。自動罰則はしない。

## 7. 期限
- 有効期限の翌日(拠点ローカル日付)以降は候補に出さない(ジョブ実行前でも日付で除外)。
- 日次ジョブが期限切れ回数券に `expire`(−残数)を記録し status=expired。冪等キー `expire:{passId}:{expires_on}`。
- 期限延長: active の間は Owner/Manager が有効期限を変更可能(監査ログ)。失効後の再有効化は `correction` で回数を戻し新しい期限を設定。
- 期限間近通知: 期限N日前(組織設定、既定7日)に顧客へ通知(冪等キー `pass_expiring:{passId}:{expires_on}`)。

## 8. 顧客統合
- 統合時は `customer_passes.customer_id` を存続顧客へ付け替える。台帳行は変更しない(回数券IDで紐付くため残数・履歴はそのまま)。

## 9. 検証
- 必須テスト #1(8回付与→1回利用→残7)、#2(同じ利用操作の二重送信→残7)、#3(取消→残8・履歴保持)、#5(期限切れは候補外)、#6(対象外サービス不可)、#18(統合後の関連)、#19(復元後の残数一致)。
- 同時消化: 同じ回数券に対し別予約から並行消化しても残数が負にならない/合計が一致すること。
