# 予約エンジン (BOOKING_ENGINE.md)

実装: `src/server/engine/availability.ts`(純関数・DB非依存) + `src/server/engine/loader.ts`(DB→入力) + `src/server/modules/bookings/allocate.ts`(確定トランザクション)。

## 1. 用語
- サービス時間 R = [start, start + duration)
- 占有時間 B = [start − beforeBuffer, start + duration + afterBuffer) … スタッフ/リソースを確保する時間
- 占有(occupancy): スタッフ・リソースの時間確保単位。1:1 は予約1件=占有1件、定員制は相乗り。

## 2. 候補開始時刻
- flexible: 拠点ローカル時刻で 0:00 から `slotInterval`(サービス設定 > 拠点設定)の倍数。R が営業区間内に収まるもの。
- fixed: `service_fixed_times`(サービス×拠点×曜日)の開始時刻。R が営業区間内に収まるもの。
- 営業区間: その日に `location_exceptions` があればそれが優先(closed → 休業, special_hours → その時間のみ)。なければ曜日の `location_hours`(複数区間可)。日付をまたぐ営業は非対応(2日に分けて設定)。

## 3. 判定条件(すべて満たす枠のみ表示/確定)

| # | 条件 | 種別 |
|---|---|---|
| 1 | 拠点が有効(公開予約は公開中のみ) | hard |
| 2 | サービスが有効・予約可(公開予約は公開中のみ)・その拠点で提供 | hard |
| 3 | 人数 ≤ サービスの1予約あたり上限、かつ ≤ 定員 | hard |
| 4 | R が拠点の営業区間内 | soft |
| 5 | R が拠点ブロック(location_blocks)と重ならない | soft |
| 6 | 受付期間: start ≥ now + 最短予約時間、start ≤ 受付上限日(拠点ローカルで今日+N日の終わり) | soft |
| 7 | スタッフ: 有効・受付可・その拠点所属・サービス対応 | hard |
| 8 | スタッフ: B がその拠点の勤務(work)シフトに完全に含まれる(連続する勤務は結合) | soft |
| 9 | スタッフ: B が休憩/休暇/研修/他業務/予約不可ブロックと重ならない(拠点を問わない) | soft |
| 10 | スタッフ: B が同スタッフの有効占有と重ならない(**他拠点を含む**)。定員制の相乗りは除く | **hard** |
| 11 | 移動時間(組織設定 travelBufferMinutes > 0 の場合): 他拠点の占有との間隔 ≥ 移動時間 | **hard** |
| 12 | リソース: 各必要条件について候補リソース(拠点所属・有効)から必要数を確保できる。容量はB内のピーク使用量で判定。メンテナンス/停止ブロックと重ならない。リソース利用可能時間(設定時)が B を含む | **hard**(容量/停止) |
| 13 | 定員: 相乗り時 seats_taken + 人数 ≤ capacity | **hard** |
| 14 | 同時受付上限(拠点設定時): R と重なる拠点の有効占有数 + 1 ≤ 上限(相乗りは増えない) | soft |

- soft は `booking.force` 権限(Owner/Manager)+ 理由入力で上書き可能(監査ログ `booking.force`)。hard は誰も上書きできない。
- 公開予約・Staff/Reception の予約は soft も上書き不可。
- スタッフ不要サービス(`requires_staff=false`、例: レンタルスペース)は 7〜11 を省略しリソースのみで判定。

## 4. おまかせ(スタッフ指定なし)
候補スタッフのうち、(1) 相乗り可能な既存占有がある、(2) その日の占有分数が少ない、(3) 表示順 の優先で自動割当。確定時に割当スタッフが埋まっていたら、おまかせ予約に限り他の候補で再判定。

## 5. 確定トランザクション
```
BEGIN
  set tenant (RLS)
  advisory lock: 冪等キー → 同じキーの予約があればそれを返す(再送でも1件)
  advisory lock (数値順): 候補スタッフ全員 / 候補リソース全て / 拠点(同時受付上限がある場合) / 顧客メール(新規顧客作成時)
  最新データを読み込み → 同じエンジンで対象枠を再判定 → 不可なら 409 SLOT_UNAVAILABLE
  占有を作成(相乗りは seats_taken を条件付き UPDATE) + occupancy_resources
  顧客の特定/作成、予約・回答スナップショット・履歴・監査・通知(outbox) を INSERT
COMMIT
```
- 排他制約違反(万一)→ 409。デッドロック/直列化失敗 → 409(再試行を促す)。
- lock_timeout 10秒。

## 6. 変更(日時/担当)・キャンセル・復元
- 変更: 予約行を `FOR UPDATE` + version 検査 → 旧占有の自席を解放 → 新しい枠を同じ判定 → 新占有を確保 → 予約更新。**失敗時はロールバックして元の予約を維持**。
- キャンセル: 自席を解放(seats_taken 減算、0 なら released)。枠は即座に再度予約可能。待機リストの候補抽出ジョブを登録。
- 無断欠席: 占有を解放(以降の時間を他の予約に使えるようにする)。
- 復元(Owner/Manager): 同じ時刻の枠を再判定して確保できた場合のみ confirmed/arrived に戻す。

## 7. 性能上の注意
- 占有・シフトの重複検索は `start < :end AND end > :start` + 下限(`start >= :from - 2日`)で B-tree 索引を使う(RLS 下で `&&` は索引条件にならない)。
- 1日分の空き計算は 1 回の読み込み(拠点・スタッフ・シフト・占有・リソース・ブロック)+ メモリ上の判定。
