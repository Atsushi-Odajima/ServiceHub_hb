ServiceHub 説明書 — サンプル組織説明
========================================

この説明書でわかること
・サンプル組織「Sample Wellness」に入っている拠点・スタッフ・サービス・
  顧客・予約などの内容
・ログイン用の5つのアカウントと、ロールごとに見える画面
・サンプル組織の作り方・作り直し方・削除のしかた
・サンプルを使ったおすすめの試し方


■ 1. サンプル組織とは

・ServiceHub を試すための組織です。パーソナルトレーニングとヨガの
  スタジオ(池袋店・新宿店の2店舗)という想定で、拠点・スタッフ・
  シフト・リソース・サービス・顧客・予約・実施記録・回数券・利用プラン・
  待機リストが最初から入っています。
・本番の組織とは別の組織として作られます。
・サンプル組織のメールは、設定にかかわらず常に送信されません。
・ログインしている間は、画面上部に「サンプル組織です(本番データでは
  ありません・メールは送信されません)」と表示されます。
・サンプルの予約ページには「これはサンプルの予約ページです。実際の予約
  は成立しません(メールも送信されません)。」と表示されます。


■ 2. 【重要】ログイン情報は公開されています

・サンプル組織のログイン用メールアドレスとパスワードは、この説明書に
  書かれており、だれでも知ることができます。
・そのため、実際のお客様が使う本番の環境には、サンプル組織を作らないで
  ください。試用のための別の環境でだけ作ってください。
・本番の環境に作ってしまった場合は、本番で使い始める前に、3章の手順で
  削除してください。


■ 3. 作り方・作り直し・削除

どれもサーバー側の作業です。運用担当者(導入を手伝う方・技術者)が
行います。コマンドは、ホスティングのシェル機能(Render の Shell など)
で実行します。Docker Compose の場合は docker compose exec app のあとに
続けて実行します。

◆ 作る
・方法1: 試用の環境の環境変数で SEED_SAMPLE_ON_START を true にして、
  起動(再起動)します。サンプル組織がまだなければ作られます。
・方法2: 次のコマンドを実行します(すでにある場合は何もしません)。
    node dist/server/cli/seed-sample.js

◆ 作り直す(日付を今日に合わせる)
    node dist/server/cli/seed-sample.js --reset
・サンプル組織を削除して、作り直します。サンプル以外の組織には触れま
  せん。
・サンプルの予約・シフトなどの日付は、作成した日を基準にしています。
  日がたつと「今日」「明日」の予約は過去のものになり、シフトも作成日から
  約60日先までしかありません。試す前に作り直すのがおすすめです。
・試した操作で変わったデータも、作り直すと最初の状態に戻ります。
・ログイン用のアカウントは作り直さず、そのまま使われます(サンプルの
  アカウントでパスワードを変更していた場合は、変更後のパスワードの
  ままです)。

◆ 削除する(本番で使い始める前に)
1. 環境変数 SEED_SAMPLE_ON_START を false にします(true のままだと、
   次の起動でまた作られます)。
2. 次のコマンドを実行します。
    node dist/server/cli/seed-sample.js --delete
・サンプル組織と、サンプル専用のログイン(@sample-wellness.example の
  アカウントで、ほかの組織に所属していないもの)が削除されます。
  本番の組織には影響しません。
※docs/OPERATIONS.md の 1.0 と 1.5 もご覧ください。

■ 13. 試してみる(おすすめの順番)

※試す前に、3章の --reset で作り直しておくと、日付が今日に合って
  分かりやすくなります。

◆ 1. オーナーで全体を見る
1. owner@sample-wellness.example でログインします。
2. ダッシュボードで「拠点の状況(今日)」「消化の確認待ち」
   「14日以内に期限の回数券」を確認します。
3. 「予定表」で、拠点や日付を切り替えて、担当者別の予定を見ます。

◆ 2. 受付モードを使う(受付)
1. iPad やスマホで reception@sample-wellness.example でログインします。
   受付台に置いたままの端末なら、「ログイン状態を保持する(受付用
   タブレット等)」にチェックします。
2. ダッシュボードの「◉ 受付モードを開く」(スマホでは画面下の「受付」)
   を押します。
3. 池袋店の今日の予約がカードで表示されます。欠席 健一(来店済み)の
   「▶ 対応開始」や、常連 太郎(対応中)の「✓ 完了へ」を押してみます。
   受付のロールでは、実施記録のメモは入力できません(「メモの記入は
   担当スタッフ・管理者が行います。」と表示されます)。
4. 「＋ 当日の予約」で、予約なしで来たお客様の予約を追加できます。
5. 別の端末でオーナーとしてログインしておくと、受付の操作が自動で
   反映されることを確認できます。

◆ 3. 完了して回数券を消化する(スタッフ Ken)
1. ken@sample-wellness.example でログインします。
2. ダッシュボードの「今日の担当」から、16:00 の残一 次郎の予約を開き
   ます(「8回券 残1」と表示されています)。
3. 「✓ 完了・実施記録」を押します。
4. 「内部メモ(スタッフのみ)」などを入力し、「回数券・利用プランの消化」
   で「8回券」を選びます。
5. 「✓ 完了して1回消化」を押し、確認の画面で「完了して1回消化」を押す
   と、残りが0回になります。
6. 完了すると、同じ画面に「次回予約を取る」が表示されます。押すと、
   同じお客様・サービス・担当で次回予約を作れます。

◆ 4. 締切後キャンセルの消化を決める(オーナー)
1. オーナーでログインし、ダッシュボードの「消化の確認待ち」から、
   期限 美咲の予約を開きます。
2. 「締切後キャンセルの消化確認」で、回数券を選んで「1回消化する」か、
   「消化しない」を選びます。確定するまで消化はされません。

◆ 5. 別の拠点の予約と重ならないことを確かめる(オーナー)
1. 「予約」→「予約を作成」を押し、顧客(例: 新規 花子)を選びます。
2. 「拠点」を新宿店、「サービス」を 60分パーソナル、「担当」を Aki に
   し、「日付」を常連 太郎の Aki の予約(池袋店 11:00)と同じ日にします。
3. 「時刻を直接指定する(営業時間外・シフト外などを理由付きで強制予約)」
   にチェックし、「開始時刻」を 11:00 にすると、「この時刻は予約できま
   せん(強制でも不可)」と表示され、理由に「スタッフはこの時間に他の
   予約があります(他拠点を含む)」が出ます。
4. 開始時刻を 12:00 にすると、拠点間の移動時間(30分)が取れないため、
   「スタッフの拠点間の移動時間が確保できません」と表示されます。
5. 確かめたら「閉じる」を押します(予約は作られません)。

◆ 6. 公開予約ページを見る
1. ログインしていないブラウザ(スマホなど)で /p/sample-wellness を開き、
   「店舗を選んでください」から池袋店か新宿店を選びます。
2. サービス → 担当 → 日時 → お客様情報 → 確認 の順に進み、「予約する」
   まで試せます。「60分パーソナル」では事前質問が表示されます。
3. 新宿店の「6名ヨガ」は、明日 19:00 の回が満席のため、その日の開始時刻
   の候補に表示されません。
4. 予約はサンプル組織の中にだけ記録されます(メールは送信されません)。
   オーナーでログインすると「予約」の一覧に表示されます。

◆ 7. 待機リストを見る(オーナー)
1. 「待機リスト」を開き、拠点を新宿店にする(または「全拠点」にチェック
   する)と、待機 誠の待機が表示されます。
2. 明日 19:00 の「6名ヨガ」の予約を1件キャンセルすると、空いた枠が
   待機の候補として表示されます。予約は自動では確定しません。


■ 14. 注意

・サンプル組織のログイン情報は公開されています。本番の環境には作らない
  でください(2章)。
・サンプル組織で操作したデータは、本番の組織には反映されません。
  本番で使う設定は、本番の組織で登録してください。
・サンプルのデータは試すうちに変わります。最初の状態に戻したいときは、
  運用担当者に --reset での作り直しを依頼してください(3章)。
