ServiceHub 説明書 — 初期設定ガイド
========================================

この説明書でわかること
・ServiceHub をインターネットに公開するまでの流れ(概要)
・最初のログインと、画面で設定を進める順番
・予約ページの確認とテスト予約のしかた
・メール送信とバックアップの準備


■ 1. 全体の流れ

1. サーバーの準備(公開作業)をする
   … 導入を手伝う方や技術者に依頼してもかまいません(2章)
2. オーナーのアカウントで初めてログインする(3章)
3. 画面で設定する(4〜12章)
   組織・運営ルール → 拠点 → リソース → スタッフ → サービス
   → シフト → メンバーと権限 → 回数券・利用プランの種類
4. 予約ページを開いて、テスト予約をする(13章)
5. メール送信を設定する(14章・運用担当者)
6. バックアップを取る(15章)
7. 最終チェックをして、本番の受付を始める(16章)


■ 2. サーバーの準備(公開作業)

この章は、サーバーの作業をする方(導入を手伝う方・技術者)向けの概要
です。詳しい手順は docs/OPERATIONS.md の「1. 構成とデプロイ」を
ご覧ください。ここに出てくる英字の名前(SETUP_ORG_SLUG など)は、
ホスティングの画面で入力する「環境変数(設定値)」の名前です。

◆ 必要なもの
・Node.js 22 が動くホスティング、または Docker が動くサーバー
・PostgreSQL 16(btree_gist という拡張機能が使えること)
・データベースに接続するユーザーは、管理者(superuser)の権限を持たない
  一般のユーザーにします。組織ごとのデータの分離をデータベースでも
  確実に行うためで、本番では管理者権限のユーザーだと起動しません。
  (付属の Render・Docker Compose の設定は、この条件を満たします。)
・公開は必ず HTTPS(https:// で始まるアドレス)で行います。

◆ 最初の組織とオーナーを作る(環境変数で行う方法・おすすめ)
初めて起動するときに次の値を入れておくと、組織・最初の拠点・オーナーの
アカウントが自動で作られます。
・SETUP_ORG_SLUG … 組織のURL名(英小文字・数字・ハイフンで3〜40文字)
  予約ページのアドレス /p/<組織のURL名> に使います。
  【注意】組織のURL名は、あとから画面で変更できません。
・SETUP_ORG_NAME … 組織名(例: マイサロン)。あとから画面で変更できます。
・SETUP_OWNER_EMAIL … オーナーのメールアドレス(ログインに使います)
・SETUP_OWNER_PASSWORD … オーナーのパスワード(10文字以上)
・SETUP_OWNER_NAME … オーナーの表示名(任意。省略すると「オーナー」)
  ※表示名は、あとから メニュー → アカウント の「表示名を変更」で変え
    られます。Render の Blueprint では入力を求められない項目です
    (その場合は「オーナー」になります)。
・SETUP_LOCATION_NAME … 最初の拠点の名前(任意。例: 本店)
  ※省略すると拠点は作られません(あとで画面から追加します)。
※タイムゾーンは Asia/Tokyo で作られます(あとから画面で変更できます)。

・自動で作られるのは、本番の組織がまだ1つもないときだけです。2回目
  以降の起動では何もしません。
・ログインを確認したら、SETUP_OWNER_PASSWORD は環境変数から必ず削除
  してください(パスワードを残さないためです)。
※コマンドで作る方法や、別の環境のバックアップから作る方法もあります
  (docs/OPERATIONS.md 1.0)。

◆ 方法A: Render(Blueprint)を使う
付属の render.yaml に、Webサービスとデータベースの定義が入っています。
1. Render にログインし、「New」→「Blueprint」で、このシステムの
   リポジトリを選びます。
2. 入力を求められる値を設定します。
   ・APP_BASE_URL … 空欄でかまいません(Render の公開URLが使われます)。
     独自ドメインにしたら、そのURLを設定します。
   ・SETUP_ORG_SLUG / SETUP_ORG_NAME / SETUP_OWNER_EMAIL /
     SETUP_OWNER_PASSWORD / SETUP_LOCATION_NAME … 上の説明のとおり
   ・EMAIL_FROM / SMTP_URL … メールを送るときに設定します。あとから
     でもかまいません(14章)。
   ・BACKUP_ENCRYPTION_KEY … バックアップを暗号化する場合(任意・15章)
   ・SESSION_SECRET は自動で作られます。値を控えて、安全な場所に保管
     してください(別の環境へ引っ越すときに同じ値を使います)。
3. プランとリージョンは、料金を Render の公式ページで確認して選びます。
   無料プランは一定時間で停止したり期限があったりするため、業務での
   利用には向きません。
4. デプロイが終わったら公開URLを開き、オーナーでログインします(3章)。
   確認できたら、Render の Environment の画面で SETUP_OWNER_PASSWORD を
   削除して保存します(再デプロイされます)。
5. 独自ドメインを使う場合は、Render の Custom Domains で設定し、
   APP_BASE_URL をそのURLに変更します。
※Render では HTTPS が自動で有効になります。

◆ 方法B: Docker Compose(自社サーバー・VPS)
1. サーバーに Docker と Docker Compose を用意し、このシステムの
   ファイル一式を置きます。
2. deploy/docker.env.example を「.env」という名前でコピーし、値を変更
   します。
   ・POSTGRES_PASSWORD / APP_DB_PASSWORD … 長いランダムな英数字
     (データベースの初回起動後に変えても反映されません)
   ・APP_BASE_URL … 公開するURL(HTTPS なら https:// から)
   ・SESSION_SECRET … 32文字以上のランダムな文字列
   ・SETUP_ORG_SLUG などの SETUP_* … 上の説明のとおり
3. docker compose up -d --build を実行します。
4. APP_BASE_URL を開き、オーナーでログインします(3章)。確認できたら
   .env から SETUP_OWNER_PASSWORD を消して、docker compose up -d を
   実行します。
5. HTTPS にするため、前にリバースプロキシ(例: Caddy、nginx)を置き、
   .env の TRUST_PROXY を true にします。

◆ 公開URL(APP_BASE_URL)の注意
・APP_BASE_URL は、利用者が実際にブラウザで開くアドレスと同じにして
  ください。違っていると、ログインや保存のときに「不正な送信元からの
  リクエストです」と表示されて操作できません。
・招待やパスワード再設定のリンクも、このアドレスで作られます。

◆ サンプル組織は作らない
・本番の環境では、SEED_SAMPLE_ON_START は false のままにしてください
  (初期値は false)。サンプル組織のログイン情報は説明書で公開されて
  いるためです(→ サンプル組織説明.txt)。


■ 3. 初めてのログイン

1. ブラウザで公開URLを開きます。ログイン画面が表示されます。
2. 「メールアドレス」と「パスワード」に、SETUP_OWNER_EMAIL と
   SETUP_OWNER_PASSWORD で決めた値を入力し、「ログイン」を押します。
   ※「ログイン状態を保持する(受付用タブレット等)」にチェックすると、
     しばらく使わなくてもログインが続きます。受付台に置いたままの専用の
     端末などで使い、ふだんのパソコンやスマホではチェック不要です。
3. ダッシュボードが表示されたら成功です。
4. サーバー作業の担当者に、SETUP_OWNER_PASSWORD の削除を依頼します。
5. パスワードを、自分だけが知るものに変えます。
   メニュー → アカウント の「パスワード変更」で、「現在のパスワード」
   「新しいパスワード」(10文字以上)「新しいパスワード(確認)」を入力し、
   「変更する」を押します。

◆ ログインできないとき
・「メールアドレスまたはパスワードが正しくありません」
  … 入力の間違いがないか確認します。
・「ログイン試行が多すぎます。15分ほど待ってからお試しください。」
  「ログイン試行が多すぎるため一時的にロックされています。…」
  … 続けて間違えると一時的にログインできなくなります。15分ほど待って
  から、もう一度試してください。
・「アクセスが集中しています。しばらく待ってからもう一度お試しください。」
  … 同じ回線から短い時間に何度もログインを試したときなどに表示され
  ます。しばらく待ってから試してください。
・「不正な送信元からのリクエストです」
  … APP_BASE_URL が、開いているアドレスと同じか確認します(2章)。

◆ パスワードを忘れたとき
・ログイン画面の「パスワードを忘れた場合」から、登録したメールアドレス
  に再設定用のリンクを送れます(リンクの有効期限は1時間)。ただし、
  メール送信を設定するまではメールが届きません(14章)。
・メールが使えない場合は、オーナーが メニュー → 設定 → メンバーと権限
  の「再設定リンク」でリンクを発行し、本人に直接渡します(24時間有効・
  1回限り)。
・オーナー自身が忘れてほかにオーナーがいない場合は、運用担当者が
  サーバーでコマンドを実行して再設定リンクを発行します
  (node dist/server/cli/reset-password.js --email <メールアドレス>。
  docs/OPERATIONS.md 7章)。
・リンクを開くと「新しいパスワードの設定」の画面になります。
  「新しいパスワード」(10文字以上)と「新しいパスワード(確認)」を入力
  して「設定する」を押し、新しいパスワードでログインし直します。


■ 4. 設定を進める順番

設定は、メニュー → 設定 から行います(すべての項目を扱えるのは
オーナーです)。スマホでは、画面下の「メニュー」から開きます。

おすすめの順番
1. 組織・運営ルール(5章)
2. 拠点 … 営業時間・定休日・臨時休業・予約ページ(6章)
3. リソース … 部屋・ベッド・スタジオ・機材(7章)
4. スタッフ(8章)
5. サービス … 所要時間・準備/片付け時間・定員・必要なリソース・
   事前質問(9章)
6. シフト … メニュー → シフト(10章)
7. メンバーと権限 … ログインの招待(11章)
8. 回数券の種類・利用プランの種類 … 使う場合だけ(12章)

拠点・リソース・スタッフを先に登録しておくと、サービスの設定で選択肢
として選べます。
拠点が2つ以上ある場合は「複数店舗の設定.txt」もあわせてご覧ください。


■ 5. 組織・運営ルール

メニュー → 設定 → 組織・運営ルール
画面の上に「公開予約URL: /p/<組織のURL名>」が表示されます。

◆ 基本情報
・「組織名」
・「タイムゾーン(組織の既定)」… 通常は Asia/Tokyo のままです。
・「公開ページの紹介文」「お問い合わせ先(公開)」
  … 予約ページの最初の画面(店舗の選択)に表示されます。

◆ 予約と拠点間移動
・「拠点間の移動時間」… 複数の拠点を兼務するスタッフがいる場合に設定
  します。「設定しない(0分)」の場合は、同じ時刻の重なりだけを防ぎます。
  設定すると、スタッフが別の拠点の予約の前後この時間内に予約を入れられ
  なくなります。
・「リマインダー送信」… 初期値は「開始の24時間前」。「送信しない」も
  選べます。
・「スタッフが自拠点の全顧客を検索できる(オフの場合は自分の担当顧客
  のみ)」… 初期値はオフです。

◆ 回数券・利用プランの消化ルール
・「完了時の消化」… 初期値は「完了時に利用可能な券を表示して確認」
・「締切後キャンセル・無断欠席」… 初期値は「運営者が消化するか確認する」
  (「消化しない」も選べます)
・「回数券の期限お知らせ(日前)」「利用プラン終了のお知らせ(日前)」
  … 初期値は7日前です。

◆ 顧客へのメール通知
・送る種類にチェックします。「予約確定」「予約変更」「キャンセル」
  「リマインダー」「空き枠のお知らせ(待機)」「回数券の期限」
  「利用プランの期限」(初期値はすべてオン)
・「返信先メールアドレス(任意)」… お客様がメールに返信したときの宛先
  です。
※メールが実際に送られるのは、メール送信を設定してからです(14章)。

最後に「保存する」を押します。


■ 6. 拠点

メニュー → 設定 → 拠点

◆ 拠点を用意する
・2章の SETUP_LOCATION_NAME で拠点を作った場合は、一覧に表示されて
  います(URL名は「main」)。拠点名を押して設定を開きます。
  【注意】この方法で作られた拠点には、営業時間が入っていません(すべての
  曜日が定休日の状態です)。必ず「営業時間」タブで設定してください。
・拠点を追加するときは「拠点を追加」を押し、「拠点名」
  「URL名(スラッグ)」(英小文字・数字・ハイフン。例: ikebukuro)
  「タイムゾーン」を入力して「追加する」を押します。営業時間は毎日
  10:00〜19:00 で作られるので、あとで変更します。
・拠点のURL名は、予約ページのアドレス /p/<組織のURL名>/<拠点のURL名>
  に使います。「基本情報・予約ルール」タブの「URL名」で変更できますが、
  公開後に変えると、以前のアドレスでは開けなくなります。

◆ 「基本情報・予約ルール」タブ
・基本情報: 「拠点名」「URL名」「住所」「電話」「メール」「タイムゾーン」
  「表示順」「公開予約ページに表示する」
・予約ルール:
  「予約の時間刻み」(初期値 30分)
  「最短予約時間(分前まで受付)」(初期値 60 = 開始の1時間前まで)
  「受付期間(何日先まで)」(初期値 60日)
  「同時受付上限(空欄=制限なし)」
  「キャンセル締切(開始の何時間前)」(初期値 24時間)
  「お客様がWebからキャンセルできる(締切前のみ)」
  「お客様がWebから日時変更できる(締切前のみ)」
  「満席時にキャンセル待ち登録を受け付ける」
・入力したら「保存する」を押します。

◆ 「営業時間」タブ(定休日もここで決まります)
・曜日ごとに営業時間を登録します。行がない曜日は定休日です。
・「+ 時間帯を追加」で行を増やし、開始〜終了の時刻を入力します。
  昼休みがある場合は、同じ曜日に2行登録します。
・「保存する」を押します。

◆ 「臨時休業・特別営業」タブ
・「日付」「種類」(「臨時休業(終日)」または「特別営業時間」)「メモ」を
  入力し、「登録する」を押します。特別営業時間の場合は「開始」「終了」
  も入力します。
・既存の予約は自動でキャンセル・移動されません。登録後に表示される件数
  を確認し、必要に応じて個別に対応してください。

◆ 「予約受付停止」タブ
・営業はするが予約を受け付けない時間(清掃・イベントなど)を、「日付」
  「開始」「終了」「メモ」で登録します。

◆ 「予約ページ」タブ
・「ご案内(予約ページ上部に表示)」
・「注意事項(確認画面に表示)」
・「テーマカラー」… 予約ページの上部の帯の色です。
・「お客様がスタッフを指名できる」… オフにすると担当者の選択画面が
  出ず、空いているスタッフが担当します。
・「価格表示を出す」… サービスの「価格表示」を予約ページに出すかどうか
・「保存する」を押します。


■ 7. リソース(部屋・ベッド・スタジオ・機材)

メニュー → 設定 → リソース
予約で使う部屋や設備を登録します。使わない場合は登録しなくてもかまい
ません。
1. 「リソースを追加」を押します。
2. 「拠点」「名称」「種類」(「部屋・施術室」「ベッド」「スタジオ」「機材」
   「車両」「その他」)「同時利用数」(同じ時間に同時に使える数。通常は1)
   「メモ」を入力し、「保存する」を押します。
・メンテナンスなどで使えない期間は、リソースの「停止期間」から登録
  できます。


■ 8. スタッフ

メニュー → 設定 → スタッフ
予約を担当する人を登録します。ここで登録するのは「スタッフの情報」で、
ログイン用のアカウントとは別です。ログインは11章の「メンバーと権限」で
招待し、スタッフの情報と紐付けます。
1. 「スタッフを追加」を押します。
2. 次の項目を入力します。
   ・「表示名(お客様に表示)」… 予約ページにも表示されます。
   ・「内部名(スタッフ間のみ)」「メール」「電話」「表示順」
   ・「予約を受け付ける」… オフにすると、新しい予約の担当になりません。
   ・「公開プロフィール」… 予約ページの担当者の選択画面に表示されます。
   ・「所属拠点(複数可)」… 兼務する場合は複数選びます。
   ・「対応サービス」… サービスを登録すると選べるようになります
     (9章のサービスの設定で選ぶこともできます)。
3. 「保存する」を押します。


■ 9. サービス

メニュー → 設定 → サービス → 「サービスを追加」
画面は「基本・予約ルール」と「拠点・スタッフ・リソース」のタブに
分かれています。両方のタブを入力してから、下の「保存する」を押します。
「事前質問」のタブは、一度保存すると表示されます。

◆ 「基本・予約ルール」タブ
・基本情報: 「名称」「カテゴリ」「価格表示(任意・表示のみ)」
  (例: 8,800円(税込)。決済は行いません)「表示順」「説明」
  「注意事項(予約時に表示)」
・時間と定員:
  「所要時間(分)」… お客様に表示される時間です。
  「準備時間 before(分)」「片付け時間 after(分)」… スタッフと部屋は
  「準備〜所要〜片付け」の間確保されます。
  「定員(同時に受ける人数)」… 1なら1対1、2以上ならクラスの形です。
  「1予約あたりの最大人数」
  「開催時刻」…「営業時間内の空き時間(刻み)」または
  「曜日ごとの固定開始時刻(クラス)」
・予約の受付:
  「時間刻み(拠点設定を上書き)」「最短予約時間(分前・空欄=拠点設定)」
  「受付期間(日先・空欄=拠点設定)」… 空欄なら拠点の設定に従います。
  「予約を受け付ける」「公開予約ページに表示する」
  「スタッフの担当が必要(オフ=部屋の貸出など)」
  「回数券を利用できる」「利用プランの対象」

◆ 「拠点・スタッフ・リソース」タブ
・「提供する拠点」… このサービスを行う拠点にチェックします。
・「担当できるスタッフ」… 担当できる人にチェックします。
・「必要なリソース(部屋・ベッド・機材など)」… 「+ 必要なリソースを
  追加」で条件を作り、「名称」「必要数」「候補リソース」を選びます。
  予約のときに、その拠点の候補のうち空いているものが自動で確保されます。
・開催時刻を「曜日ごとの固定開始時刻(クラス)」にした場合は、
  「固定開始時刻(クラスの時間割)」で拠点・曜日・時刻を選んで「追加」
  します。

◆ 「事前質問」タブ
・予約のときにお客様に答えてもらう質問です。「+ 質問を追加」で、
  「質問文」「回答形式」(「短文」「長文」「単一選択」「複数選択」
  「はい/いいえ」「確認(同意)」)「補足説明」「必須」を設定し、
  「事前質問を保存」を押します。
【注意】事前質問は予約の準備のための簡単な確認用です。病歴・症状など
医療問診の用途には使用しないでください。


■ 10. シフト

メニュー → シフト(「設定」の中ではありません)
【注意】スタッフが担当するサービスは、そのスタッフのその拠点での
「勤務」のシフトの時間内でしか予約を受け付けません(オーナー・
マネージャーが理由を入力して強制予約する場合を除きます)。シフトが
ないと、予約ページに空き時間が表示されません。
・拠点が2つ以上ある場合は、画面上部で拠点を選びます。表には、その拠点に
  所属するスタッフが表示されます。

◆ 週テンプレートを作る
1. スタッフ名の下の「週テンプレート」を押します。
2. 「+ 行を追加」で、曜日・種類(「勤務」または「休憩」)・拠点・開始〜
   終了を入力し、「保存する」を押します。

◆ テンプレートからシフトを作る
1. 「テンプレートから生成」を押します。
2. 「開始日」「終了日」を選んで「生成する」を押します(最大92日)。
   すでにシフトがある日は上書きせずにスキップし、定休日・臨時休業日も
   スキップします。

◆ 1日ずつ登録・変更する
・表のマスの「+ 追加」で、その日のシフトを登録できます。「種類」
  (「勤務」「休憩」「休暇」「研修」「他業務」「予約不可」)「拠点」
  「開始」「終了」「メモ」を入力して「保存する」を押します。
・登録済みのシフトを押すと、変更・削除できます。
・既存の予約と重なる変更をすると、警告が表示されます。予約は自動で
  削除・移動されません。


■ 11. メンバーと権限(ログインの招待)

メニュー → 設定 → メンバーと権限
一緒に使う人に、ログイン用のアカウントを作ってもらいます(招待)。
1. 「メンバーを招待」を押します。
2. 「メールアドレス」と「ロール」を入力します。
   ・オーナー — 全設定・全拠点・分析・スタッフ・権限
   ・マネージャー — 担当拠点の予約/顧客/シフト/受付/KPI
   ・スタッフ — 自分の予約・担当顧客・実施記録・次回予約
   ・受付 — 担当拠点の予約受付・来店処理・顧客検索(経営情報/機密メモは
     不可)
3. オーナー以外は「担当拠点」を選びます(「全拠点(今後追加する拠点を
   含む)」または拠点ごと)。
4. 予約を担当する人は「スタッフとして予約を担当する場合の紐付け」で、
   8章で登録したスタッフを選びます。スタッフロールの人は、紐付けた
   スタッフの予約・顧客だけを操作できます。
5. 「招待メールを送信する」にチェックしたまま「招待する」を押します。
6. 「招待を作成しました」の画面に「招待リンク」が表示されます(7日間
   有効)。メール送信を設定していない間は招待メールが届かないので、
   このリンクをコピーして本人に直接渡します。
   ※リンクが表示されるのはこのときだけです。控え忘れた場合は、同じ
     メールアドレスでもう一度招待してください(前の招待は無効になり
     ます)。
7. 招待された人がリンクを開き、「表示名」「パスワード」(10文字以上)
   「パスワード(確認)」を入力して「参加する」を押すと、メンバーになり
   ます。すでに ServiceHub のアカウントがある人は、「既存アカウントの
   パスワード」を入力します。

・一覧の「権限を編集」でロール・担当拠点・スタッフ紐付けを変更、
  「無効化」でログインを止められます。変更はすぐに反映されます。
・パスワードを忘れた人には「再設定リンク」を発行して直接渡せます
  (24時間有効・1回限り)。
・オーナーは最低1人必要です。万一に備えて、信頼できる人をもう1人
  オーナーにしておくことをおすすめします。
・詳しくは「スタッフと権限.txt」をご覧ください。


■ 12. 回数券の種類・利用プランの種類

使う場合だけ設定します。どちらも料金の決済は行いません。
・回数券: メニュー → 設定 → 回数券の種類 →「追加」で、回数・有効期間・
  対象サービスを登録します(→ 回数券の使い方.txt)。
・利用プラン: メニュー → 設定 → 利用プランの種類 →「追加」で、期間内の

  (→ 利用プランの使い方.txt)。


■ 13. 予約ページの確認とテスト予約

◆ 予約ページのアドレス
・組織のトップ(店舗の一覧): <公開URL>/p/<組織のURL名>
・拠点の予約ページ: <公開URL>/p/<組織のURL名>/<拠点のURL名>
  例: https://reserve.example.com/p/my-salon/main
・組織のURL名は「組織・運営ルール」の画面の上部、拠点のURL名は
  「拠点」の一覧の「URL名」の列で確認できます。

◆ テスト予約をする
1. スマホやパソコンで、拠点の予約ページを開きます(管理画面に
   ログインしていないブラウザで開くと、お客様と同じ見え方になります)。
2. 「サービスを選んでください」でサービスを選びます。
3. 「担当者を選んでください」が表示されたら、スタッフか「おまかせ」を
   選びます。
4. 日付を選び(○=空きあり ×=空きなし)、開始時刻を選んで「次へ」を
   押します。
5. 「お名前」「メールアドレス」「電話番号」(必須)などを入力し、事前質問
   があれば答えて「確認へ」を押します。テストなので、自分のメール
   アドレスと「テスト」などの名前を使ってください。
6. 「予約内容の確認」で「上記の内容と注意事項を確認しました」にチェック
   し、「予約する」を押します。
7. 「✓ ご予約が確定しました」と予約番号が表示されれば成功です。
   メール送信を設定していない間は、「現在この予約ページからは確認メール
   が送信されません。…」と表示されます。
8. 管理画面の「予定表」や「予約」に、テスト予約が表示されることを
   確認します。
9. 確認が終わったら、予約の詳細で「キャンセル」を押し、
   「キャンセルの区分」を選んで「キャンセルする」を押します。テスト用の
   顧客は、顧客の詳細で「アーカイブ」すると一覧に表示されなくなります。

◆ 空き時間が表示されないとき(確認すること)
・拠点の「営業時間」が入っているか(行がない曜日は定休日です)
・その日に「臨時休業」や「予約受付停止」が入っていないか
・スタッフの「勤務」のシフトが、その拠点・その日に入っているか
・スタッフの「所属拠点」にその拠点が入っているか、そのサービスを
  担当できるか(「対応サービス」または「担当できるスタッフ」)、
  「予約を受け付ける」がオンか
・サービスの「提供する拠点」にその拠点が入っているか、「予約を受け
  付ける」「公開予約ページに表示する」がオンか
・「必要なリソース」を設定した場合、その拠点のリソースが「候補リソース」
  に入っているか
・「最短予約時間」(初期値は開始の60分前まで)と「受付期間」(初期値は
  60日先まで)の範囲内か
※拠点の「公開予約ページに表示する」がオフだと、予約ページそのものが
  開けません。サービスが1つも表示されないときは「現在Webで予約できる
  サービスはありません」と表示されます。


■ 14. メール送信の設定

・初期の状態では、メールは送信されません(送信せずに記録だけが残り
  ます)。「通知履歴」には「現在メール送信は設定されていません(ログ出力
  のみ)。本番運用では EMAIL_PROVIDER=smtp を設定してください。」と
  表示されます。
・メール送信を設定するまでは、次のようになります。
  ・予約確定・リマインダーなどのメールは、お客様に届きません。
  ・メンバーの招待は、招待リンクを直接渡します(11章)。
  ・パスワードを忘れた人には、オーナーが「メンバーと権限」の
    「再設定リンク」を発行して渡します。

◆ 設定のしかた(運用担当者が行います)
1. SMTP に対応したメール送信サービスを用意し、送信用のサーバー名・
   ユーザー名・パスワードなどを確認します。
2. ホスティングの環境変数(Docker の場合は .env)に次を設定します。
   ・EMAIL_PROVIDER … smtp
   ・SMTP_URL … 送信サーバーへの接続先
     例: smtps://ユーザー名:パスワード@smtp.example.com:465
   ・EMAIL_FROM … 送信元の表示
     例: マイサロン <no-reply@example.com>
3. システムを再起動します(Render は保存すると再デプロイされます。
   Docker は docker compose up -d を実行します)。
   ※EMAIL_PROVIDER を smtp にしたのに SMTP_URL が空だと、システムが
     起動しません。
4. 送信元のドメインに SPF・DKIM・DMARC を設定します(メール送信
   サービスの案内に従います)。設定しないと、迷惑メールと判定されたり
   届かなかったりすることがあります。
5. 自分のメールアドレスでテスト予約をして、メールが届くことと、
   「通知履歴」の状態が「送信済み」になることを確認します。
※メール送信を設定する前に作られた通知は、あとから送信されません。
※送るメールの種類とリマインダーの時間は「組織・運営ルール」で選べます
  (5章)。


■ 15. バックアップ

・設定が終わったら、最初のバックアップを取っておきます。
  メニュー → 設定 → バックアップ →「バックアップを作成してダウンロード」
・ファイルには、顧客の個人情報とログイン情報が含まれます。メールや
  チャットで送らず、アクセスを制限した場所に保管してください。
・週1回以上と、大きな設定変更・CSVの取り込み・アップデートの前に作成し、
  最低でも直近3世代を残すことをおすすめします。
・暗号化したい場合は、運用担当者が環境変数 BACKUP_ENCRYPTION_KEY
  (16文字以上)を設定します。キーを失うと復元できないため、ファイル
  とは別の場所に保管します。画面の「暗号化: 有効」「暗号化: なし」で
  状態がわかります。
・ホスティングのデータベースのバックアップ機能とも併用してください。
・詳しくは「バックアップと復元.txt」をご覧ください。

■ 追加された設定(予約・受付まわり)
--------------------------------------------------
(1) 店舗へのメール通知 … 「設定」→「組織・運営ルール」→「店舗へのメール通知」
  お客様がWebで予約・日時変更・キャンセルしたとき、またはキャンセルで空いた枠に
  キャンセル待ちの該当者がいるときに、店舗へメールでお知らせします。
  通知先が空欄の場合は「返信先メールアドレス」に送ります。種類ごとに止められます。
  スタッフが画面で操作した予約・キャンセルでは送りません。

(2) メールの署名 … 同じ画面の「メールの署名」
  お客様宛てのメール(予約確認・リマインダーなど)の最後に入ります。

(3) 予約ページの追加設定 … 「設定」→「拠点」→ 各拠点 →「予約ページの表示」
  ・電話番号の入力: 必須 / 任意 / 聞かない
  ・Webからの日時変更の締切: キャンセルの締切と別にしたい場合だけ入力します
  ・同意事項: 予約の確認画面に表示し、同意のチェックを求めます
  ・予約完了画面のメッセージ
  ・ご案内(持ち物・アクセスなど): 確認画面・予約確認メール・リマインダーに表示されます
  ・ホームページ / SNS のURL(https:// で始まるもの)

(4) 全サービス共通の事前質問 … 「設定」→「サービス」の一覧の下
  どのサービスを予約しても表示される質問です。サービスごとの質問より先に表示されます。

(5) お客様用リンクの再発行 … 予約の詳細画面「お客様用の予約管理リンク」
  お客様がリンクをなくした、または他の人に知られた場合に、新しいリンクを発行します。
  以前のリンクは使えなくなります。「無効にする」でリンクを止めることもできます。

(6) 受付方法 … 予約を作成するときの「受付方法」
  電話・来店・DM・メールなど、どこから受けた予約かを記録できます。予約CSVにも出力されます。

(7) 予約のカレンダー出力 … 「CSV」→ 種類「予約」→「カレンダー形式(.ics)で出力」
  期間内の予約を、Googleカレンダーなどに取り込める形式でまとめて出力します。
